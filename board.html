1一期做什么 · 目标

以下内容全部摘自主文档《CID 方案 · 一期简化版（保留 TID）》（@michaelpei），此处只做摘要，细节以文档为准。

0708 决策变更：v3 版本目标是「下线 TID」、改动涉及全链路；最新决策为保留 TID、只在召回/粗排环节做局部升级。原阶段 2b 中 TID 下线相关新库表设计、创意组件化改造及渲染侧卷入均取消。
一期做什么
引入 CID（创意主视觉 ID = 主视觉指纹 + 创意形式）作为中间粒度，只在召回/粗排把排序颗粒度从 TID 切到 AID_CID。

一期目标
机器资源基本持平前提下，召粗承载指纹容量提升至 3 倍。
视频号当前在线 5900w TID ≈ 737w 指纹 → 提升后约 2200w 指纹（≈1.8 亿 TID）。Embedding 总量「700w aid + 5000w tid」→「700w aid + 1000w cid」。

02 · 红线扩容收益验证（我主导）
当前最重要的事
推动各方本周把两个前置项落地（前置数据 + 打标口径），让实验方案定稿、进入开发排期 —— 让「扩容到底值不值」尽快变成一个可实验、可回答的问题。

1项目背景 · 为什么做

1
扩容的收益从来没被干净地证明过。在线创意容量红线长期截断，业务持续要求扩容；但扩容要花真金白银的机器成本，而此前的整体扩容尝试看不到明显跑量差别（疑似只是摊平了冷启动），没有团队敢为扩容提单。
2
价值：这是容量策略的分叉路口。如果扩容被证明有增量收益，就应该花钱扩、并按收益决定扩多少；如果没有，就坚定走「降 ID 数」（CID 项目）的路线。验证结论同时是 CID 二期容量目标口径的直接输入 —— 两条路线用同一个实验校准。
3
为什么以前测不出来：整体扩容时各召回链路互相影响、增量创意的贡献被稀释和污染。要回答这个问题，必须做隔离式的对照实验（hold-out）：给扩容增量创意打标，实验组流量屏蔽这些创意来模拟「未扩容」，与对照组比消耗差。

2项目现状 · 现在怎么样

1
实验方法已定：hold-out 反向实验的整体设计已获各方认可，正在收敛为可开发的方案。
2
核心难点已摸清：召回系统有一个强约定 —— 同一广告在不同召回链路下的创意必须严格一致，导致无法简单地「只对某一条链路」做隔离；同时每条链路单独建实验环境的部署成本很高。这正是此前实验测不干净、也是本项目方案设计的关键约束。
3
方案框架已收敛（两轮讨论）：按链路分类处理 —— 消耗占比最高的创意主路（约一半消耗）优先做隔离实验；广告级联链路用低成本的过滤方案替代独立建设；生成式链路架构复杂且在快速迭代、实验成本过高，暂缓、视创意主路结果再定；长尾小链路不做隔离（残留误差可接受）。打标口径已定原则：不与既有实验冲突、创意入库即打标。
4
当前卡在两个前置项：(a) 前置数据 —— 新旧候选集选出的优质创意重合度：若高度重合，多数链路根本不需要建实验环境，建设成本可大幅压缩；(b) 打标口径的最终确认 —— 打标时机不对会让前置数据失真。两项落地后即可定稿方案、进入开发排期（外部依赖机器申请与环境部署，约两周）。

3项目 To-do · 现在要做什么

本周产出前置数据：新旧候选集「优质创意」重合度对比数据侧
本周打标口径最终确认（创意入库即打标，不与既有实验冲突）数据 / 工程侧
数日内输出完整实验改造方案（含生成式链路的处理结论）检索侧
定稿后机器申请与实验环境部署（约两周）→ 开发 → 实验上线工程 / 运维

03 · 商分调研 Agent 评测（自有项目）
当前最重要的事
把评测流程跑通第 0 轮：10 道长报告题 × 3 个 candidate 盲评 —— 第 0 轮同时产出两样东西：一套可复现的评价标准，和 Agent 当前的水位分。评测不是终点，它启动的是「评测 → 归因 → 优化 → 再评测」的迭代闭环，循环至达到上线标准。

1项目现状

1
商分深度调研 Agent 已能产出完整长报告，项目进入「用评测证明水平、并驱动迭代」的阶段。
2
评测体系设计已完成初稿（下方框架），解决了两个关键问题：评什么 —— 只评用户真正看到的端到端结果，技术指标作门槛、能力维度只用于内部归因；怎么保证可复现 —— 人评天然漂移，所以第 0 轮先用盲评+评语抽取出固定的评价标准，之后每轮按同一标准执行。
3
我们的定位判断：这个 Agent 拼的不是通用编排能力，而是「更懂商分团队的需求」。评测因此回答两个问题：有没有达到「可以给老板交作业」的水平（跟自己的标准比）；相比通用工具到底强多少（跟基线比）。

2评测框架（我们的设计）

层内容用途
Tech 门槛稳定性（不吐字/不 fail）、任务时长（≤2h）、流程完整度（≥90% 完整跑完）must-have，yes/no 过线，不进评分
Result 评分（唯一计分）端到端长报告质量：人评 1–5 星 + 自由评语，盲评混排；第 0 轮后按固化维度评对外汇报的唯一分数
Capability 归因上下文抓取、issue tree 拆解正确性、调研充分度（可用 arena 两两对比）内部定位「哪块不行」，驱动迭代

3评测 → 迭代闭环（评完就改，改完再评）

评测的价值不在打分，而在驱动 Agent 一轮轮变好 —— 直到达到上线标准（技术门槛全过 + 结果达到目标星级），推给团队日常使用。
